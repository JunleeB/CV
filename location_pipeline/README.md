# 실내 홈캠 객체 위치 추론 파이프라인

![Python](https://img.shields.io/badge/Python-3776AB?logo=python&logoColor=white)
![PyTorch](https://img.shields.io/badge/PyTorch-EE4C2C?logo=pytorch&logoColor=white)
![FastAPI](https://img.shields.io/badge/FastAPI-009688?logo=fastapi&logoColor=white)
![Ultralytics](https://img.shields.io/badge/YOLO11-Ultralytics-00FFFF?logoColor=black)

> [CCTV 객체 위치 추론 프로젝트](../docs/project_c_vlm.md)(시니어 레지던스 고객사 건)에서 겪은
> "VLM 단독 추론의 비용·확장성 한계"를 이어받아, 회사 자체 데이터로 진행한 별개의 내부 연구용
> 후속 작업입니다. 특정 고객사 계약과는 무관합니다.
>
> 아래 1~3단계는 개인 작업물이거나 회사 소유 IP가 섞여 있어 **개요 설명으로만** 남겼습니다.
> 실제 코드가 포함된 건 4단계(REACT++ 비교 실험, [`react_pp_comparison/`](react_pp_comparison/))
> 뿐이며, 이는 공개 오픈소스 프레임워크를 우리 데이터로 파인튜닝한 부분이라 코드로 공개합니다.

홈카메라 영상에서 지갑·스마트폰·안경·리모컨·시계 같은 소형 이동 물체를 탐지하고, "손에 있다 /
테이블 위에 있다 / 착용 중이다" 같은 위치 정보까지 라벨링하는 파이프라인을 VLM 기반 프로토타입에서
시작해 규칙기반 엔진, 비디오 트래킹 검수 툴, Scene Graph Generation 모델 비교까지 단계적으로
고도화한 기록입니다.

## 전체 흐름

```
1단계  VLM(Qwen3-VL) 기반 위치 GT 생성
        └ 소규모 파일럿에서 동작 확인, 그러나 프레임마다 VLM 호출 필요 → 비용·지연 문제

2단계  YOLO11 탐지 + YOLO11-pose + 규칙기반 엔진
        └ VLM 호출을 제거하고, 얼굴/손 키포인트 근접도 + 가구 포함관계 기반의
          결정론적 규칙으로 위치 판정 (비용 0, 지연 없음, 판정 근거 100% 설명 가능)

3단계  SAM2 비디오 트래킹으로 검수 파이프라인 고도화
        └ 프레임을 독립적으로 추론하던 YOLO 대비, 시드 프레임 1장 기준으로 물체를
          시간축으로 추적해 오분류·중복탐지·드리프트 같은 오류 빈도를 낮춤

4단계  Scene Graph Generation(REACT++)과의 비교 실험   → react_pp_comparison/
        └ 우리 데이터로 REACT++를 파인튜닝해, 규칙기반 접근과 학습 기반 SGG 접근의
          트레이드오프를 실험적으로 비교 (코드 포함)
```

각 단계는 독립적으로 동작하는 게 아니라, 이전 단계에서 부딪힌 한계(비용, 검수 노동량, 규칙기반의
경직성)를 다음 단계가 이어받아 개선하는 구조입니다.

---

## 1단계 — VLM 기반 위치 GT 생성

Qwen3-VL을 vLLM으로 서빙해, YOLO 라벨의 bbox를 크롭해서 "이 물체가 어디 있나?"만 질문하는 방식으로
위치 GT를 생성했습니다. (전체 이미지에서 탐지+위치를 동시에 물으면 정확도가 떨어져서, bbox 단위로
쪼개 질문하는 방식으로 정착.) 이렇게 만든 위치 GT는 4단계 REACT++ 파인튜닝의 관계 라벨 소스로도
재사용됩니다.

**한계**: 소규모 파일럿에서는 잘 동작했지만, 프레임마다 VLM API를 호출해야 해서 처리 규모가
커질수록 비용·지연이 선형으로 증가 → 2단계에서 규칙기반으로 대체.

## 2단계 — 규칙기반 위치 판정 엔진

VLM 호출을 걷어내고, YOLO11-pose로 뽑은 사람 키포인트(코·눈·손목)와 물체 박스 사이의 기하학적
근접도, 가구 박스와의 포함관계(containment)만으로 위치를 판정하는 규칙엔진으로 대체했습니다.

- 판정 우선순위: 얼굴 근접 → 손목 근접 → 가구 포함관계 → 바닥
- VLM 대비 호출 비용 0, 응답 지연 없음, "왜 이 답이 나왔는지" 규칙 단위로 100% 역추적 가능
- 대신 규칙에 없는 애매한 자세/각도에는 취약 — 실제로 클래스별 예외 처리(시계→손목, 얼굴에 댄 폰→손)를
  계속 추가하며 보완
- 이 로직은 제가 직접 설계·구현했지만 **회사 소유 IP**라 소스코드는 올리지 않았습니다

## 3단계 — SAM2 트래킹 + 반자동 검수 툴

1·2단계로 만든 최종 결과(박스+클래스+위치)를 사람이 웹에서 검토·수정하는 반자동 라벨링 툴을 먼저
구축했고, 이후 검수 대상을 넓히는 방법으로 SAM2 비디오 트래킹을 도입했습니다. 검수자가 세션 내
프레임 1장(시드)의 결과를 확정하면, SAM2 video predictor가 같은 물체를 지정 구간 전체에 걸쳐
추적하고, 매 프레임 규칙기반 위치추론을 재실행합니다.

**핵심 개선점**: 기존 YOLO는 프레임마다 독립적으로 추론해서 오분류·중복탐지·드리프트 같은 오류가
프레임 단위로 개별 발생했습니다. SAM2는 시드 프레임 1장의 정답을 기준으로 물체를 시간축으로 이어서
추적하기 때문에 프레임 간 일관성이 높아지고, 결과적으로 검수자가 수정해야 하는 빈도가 줄었습니다.
(검토 자체가 필요 없어지는 건 아니고, "매 프레임 새로 그리기"에서 "추적 결과 검토+보정"으로 노동의
종류가 바뀐 것입니다.)

### 트러블슈팅 하이라이트

- **세그멘테이션 마스크 결손** — 사람이 소파에 앉으면 SAM2 마스크가 좌우로 갈라지는 문제 발생.
  처음엔 연결영역을 병합하는 방식으로 시도했으나 근본 원인(마스크 자체가 반쪽만 인식)과 달라 미해결.
  최종적으로 고정 카메라 특성을 활용해 **가구 박스는 SAM2 재추적 대신 시드프레임 박스를 구간 전체에
  고정**하는 방식으로 전환해 해결.
- **다중 검수자 동시쓰기로 인한 결과 파일 손상** — 검수자의 웹 저장과 배치 job의 파일 저장이 겹치며
  JSON이 손상되는 문제를, 손상 파일 안의 서로 다른 부동소수점 정밀도를 단서로 원인을 특정하고,
  임시파일 작성 후 원자적 교체(atomic rename) 방식으로 전환해 해결.
- **누락 프레임으로 인한 배치 job 크래시** — 트래킹 대상 프레임 목록 구성 시 실제 파일 존재 여부를
  먼저 검증하도록 방어 로직 추가.

## 4단계 — REACT++(Scene Graph Generation)와의 비교 실험 (`react_pp_comparison/`)

규칙기반 엔진이 "제한된 클래스 + 제한된 관계(on/in hand/wearing)"만 다루는 반면, Scene Graph
Generation은 임의의 물체 클래스 쌍에 대해 훨씬 다양한 관계를 표현할 수 있는 일반적인 문제입니다.
우리 도메인에 이런 학습 기반 접근이 어느 정도 통하는지 확인하기 위해, 공개 오픈소스 프로젝트
[SGG-Benchmark](https://github.com/Maelic/SGG-Benchmark)의 REACT++ 모델을 우리 데이터로
파인튜닝하는 실험을 진행했습니다. 자세한 코드는 [`react_pp_comparison/`](react_pp_comparison/) 참고.

- `convert_homeai.py` — VLM이 생성한 위치 GT(1단계 산출물, `gt_locations/*.jsonl`)를 SGG용 관계
  트리플릿(subject, predicate, object)으로 변환. `on the sofa` → `(물체, on, sofa)`,
  `in hand` → `(물체, in hand, person)`, `on the wrist`/`on the face` → `(물체, wearing, person)` 등으로 매핑
- `react_pp_ft_config.yml` — REACT++ 백본을 우리 YOLO11m 탐지기로 교체하고, 물체 12클래스·관계
  4클래스(우리 도메인에 맞게 축소)로 파인튜닝한 실제 설정

**실험 결과**: REACT++는 규칙기반이 확실히 틀렸던 케이스의 약 70%를 개선했지만, 전체 정확도·
처리속도는 규칙기반 대비 약간 낮았습니다(프레임 정확도 **0.818 vs 0.826**, 속도 **23.4fps vs
30.9fps**). 소형 물체 특유의 작은 feature map, 학습 데이터가 4개 관계 클래스로 제한된 점,
frequency prior가 IndoorVG가 아닌 우리 데이터 기준으로 재계산된 점 등이 원인으로 추정되며, "학습
기반 SGG로 완전히 대체 가능한가"보다는 "이 도메인에서 두 접근의 트레이드오프가 무엇인가"를
확인하는 실험적 성격이 강합니다.

## 한계 / 정직하게 밝히는 부분

- 검수자가 트래킹 구간의 결과를 전부 한 번씩은 훑어봐야 함 — "1장만 보면 끝"이 아니라 오류 빈도가
  줄어든 것
- 원자적 쓰기로 파일 손상은 막았지만, 동시 편집 시 한쪽 수정이 통째로 유실되는 경합은 여전히 남아있음
- 규칙기반 위치판정은 "가구·카메라가 고정돼있다"는 도메인 가정에 강하게 의존 — 이동 카메라 환경에는
  재설계가 필요
- REACT++ 비교 실험은 학습 데이터 4개 관계 클래스로 축소·frequency prior 재계산 등 제약이 있어,
  "일반적인 SGG 모델 대비 성능"이 아니라 "이 도메인에 한정된 트레이드오프 실험"으로 해석해야 함
