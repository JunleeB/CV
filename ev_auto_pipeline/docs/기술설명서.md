## 1. 시스템 개요

EV 자동 어노테이션 시스템은 **전기차(EV) CCTV 주차장 영상**에서 객체(차량, 화재, 연기 등)를 자동으로 탐지·분할하고 어노테이션을 생성하는 웹 기반 플랫폼이다.

### 핵심 기능

| 기능 | 설명 |
|------|------|
| 자동 어노테이션 | YOLO11 + SAM2로 이미지 배치 자동 레이블링 |
| 제로샷 탐지 | Grounding DINO로 학습 없이 화재·연기 탐지 |
| 인터랙티브 SAM2 | 사용자 클릭(bbox/포인트) → 즉각 마스크 생성 |
| 비디오 트래킹 | SAM2 Video Predictor로 프레임 간 객체 전파 |
| 파인튜닝 | 어노테이션 데이터로 YOLO 모델 재학습 |
| 다중 포맷 내보내기 | YOLO/COCO/VOC/CSV 형식 지원 |
| 리뷰 시스템 | 신뢰도 낮은 탐지 결과 검토 큐 |

## 3. 인프라 및 GPU 구성

### GPU 할당

```
CUDA_VISIBLE_DEVICES=2,5
                │       │
                │       └── cuda:1 → Grounding DINO 추론 (물리 GPU 5)
                └────────── cuda:0 → YOLO + SAM2 추론 (물리 GPU 2)

GPU 3 → YOLO 파인튜닝 (독립 프로세스, CUDA_VISIBLE_DEVICES=3)
```

> **주의**: 추론 서버와 학습 프로세스가 다른 GPU를 사용하므로, 학습 중에도 실시간 추론이 가능하다.

### Docker 컨테이너

| 컨테이너 | 이미지 | 포트 | 용도 |
|---------|--------|------|------|
| ev_postgres | postgres:15 | 5432 | 주 데이터베이스 |
| ev_pgadmin | pgadmin4 | 5050 | DB 관리 UI |

PostgreSQL 데이터는 `ev_auto_pipeline/pgdata/`에 바인드 마운트되어 컨테이너 재시작 시에도 보존된다.

### 연결 문자열

```
postgresql://evuser:REDACTED@localhost:5432/annotation
```

SQLAlchemy 연결 풀: `pool_size=10`, `max_overflow=20`, `pool_recycle=3600s`, `pool_pre_ping=True`

### 4.3 추론 엔진 (inference.py)

#### 모델 캐시 구조

```python
# YOLO: 가중치 경로별 지연 로딩
_yolo_cache: dict[str, YOLO] = {}

# SAM2: (이미지경로, mtime) 키, LRU 20개 제한
_sam_cache: OrderedDict[(img_path, mtime), (features, orig_hw)]

# Grounding DINO: 모델 ID별 캐시
_gdino_cache: dict[str, (model, processor)] = {}
```

#### SAM2 임베딩 캐시 효과

| 상태 | 지연시간 |
|------|---------|
| 캐시 미스 (첫 클릭) | ~1,000ms |
| 캐시 히트 (재클릭) | ~50ms |

같은 이미지에 반복 클릭할 때 SAM2 이미지 인코딩(CNN forward pass)을 재사용하므로 약 **20배** 빠르다.

#### 주요 추론 함수

**`run_inference(img_path, conf_threshold, yolo_conf_min, roi, weights_path)`**
- YOLO 탐지 → SAM2 세그멘테이션 → 다각형 마스크 출력
- ROI 필터: 탐지 bbox가 ROI 폴리곤과 겹치지 않으면 제외
- 클래스 간 IoU 억제: 다른 클래스 간 겹침이 크면 신뢰도 낮은 쪽 제거
- `conf >= conf_threshold` → `auto_labels` (자동 완료)
- `conf < conf_threshold` → `review_items` (검토 대기)

**`run_inference_detect(img_path, conf_threshold, yolo_conf_min, roi, weights_path)`**
- YOLO만 사용 (SAM2 없음), 직사각형 bbox를 4-point 폴리곤으로 출력
- `run_inference`와 동일한 반환 형식 (drop-in 대체 가능)

**`run_inference_gdino(img_path, conf_threshold, roi, weights_path)`**
- Grounding DINO 제로샷 탐지 (화재·연기 특화)
- 텍스트 프롬프트: `"fire . smoke"` (fire를 앞에 배치해 클래스 매핑 정확도 향상)
- 임계값: `box_threshold=0.15`, `text_threshold=0.15`
- ROI crop 최적화: ROI 영역만 잘라서 추론 → 소형 객체 감지율 향상
- 후처리 파이프라인:
  1. 대형 박스 필터 (연기: 이미지 면적 40% 초과, 화재: 70% 초과 제거)
  2. 밝기 기반 트리밍 (`_brightness_trim_bbox`) — 불꽃 주변 반사광 제거
  3. SAM2로 타이트한 bbox 재계산 (`_sam_tight_bbox`)
  4. 겹치는 박스 병합 (`_merge_overlapping`, IoU > 0.3, Union-Find 알고리즘)
  5. 신뢰도 기준으로 auto / review 분류

**`sam_predict_bbox(img_path, bbox_norm)`**
- 사용자가 그린 bbox → SAM2 마스크 → 정규화 폴리곤 반환
- 캐시 활용으로 빠른 응답

**`sam_predict_points(img_path, points_norm, point_labels)`**
- 포인트 클릭(양성/음성) → SAM2 마스크
- 여러 클릭 포인트를 누적해서 마스크 정밀도 향상

**`run_sam2_video_track(image_paths, seed_bboxes_norm, seed_class_ids, bbox_only, progress_cb)`**
- SAM2 VideoPredictor로 프레임 간 객체 전파
- 시드 프레임(frame 0)의 bbox → 이후 프레임들의 마스크/bbox 예측
- `bbox_only=True` → 직사각형 bbox 출력 (detect 형식)
- `bbox_only=False` → 다각형 마스크 출력 (segment 형식)
- 진행 콜백(`progress_cb`)으로 WebSocket 스트리밍 지원

#### 헬퍼 함수

| 함수 | 역할 |
|------|------|
| `mask_to_polygon(mask)` | OpenCV 컨투어 → 정규화 좌표 배열 |
| `_roi_crop_box(roi, w, h)` | ROI 폴리곤의 bbox 계산 |
| `_in_roi(bbox, roi, w, h)` | 탐지 bbox ∩ ROI 겹침 여부 |
| `_iou(a, b)` | Intersection-over-Union 계산 |
| `_suppress_cross_class(detections)` | 클래스 간 IoU 억제 |
| `_brightness_trim_bbox(img, bbox)` | 밝기 기반 bbox 트리밍 |
| `_merge_overlapping(boxes)` | Union-Find 기반 bbox 병합 |
| `_sam_tight_bbox(img_path, bbox)` | SAM2로 bbox 정밀 재계산 |

| PATCH | `/api/images/{image_id}/status` | 상태 변경 |
| POST | `/api/images/{image_id}/sam-bbox` | SAM2 bbox → 마스크 |
| POST | `/api/images/{image_id}/sam-points` | SAM2 포인트 → 마스크 |

어노테이션 저장은 항상 **원자적 교체** 방식: 기존 것을 전부 삭제하고 새로 저장.

#### jobs.py — 자동 어노테이션 잡

| 메서드 | 경로 | 설명 |
|--------|------|------|
| POST | `/api/projects/{project_id}/jobs` | 자동 어노테이션 잡 시작 |
| GET | `/api/jobs/{job_id}` | 잡 상태 조회 |
| WS | `/ws/jobs/{job_id}` | 진행상황 실시간 스트리밍 |
| POST | `/api/projects/{project_id}/track` | SAM2 비디오 트래킹 잡 시작 |

**잡 실행 흐름 (`_run_job`)**:
```
1. project.model_id → ModelVersion 조회
2. task 타입에 따라 추론 함수 선택:
     segment → run_inference()
     detect  → run_inference_detect()
     gdino   → run_inference_gdino()
3. 이미지를 filename 순 정렬 (프레임 순서 보장)
4. gdino 태스크: FrameTracker 적용
     - IoU 기반 프레임 간 추적
     - 6프레임 이상 정적 박스 억제 (고정 오탐 제거)
     - 최대 3프레임 미탐지 전파 (신뢰도 감소)
5. 각 이미지 처리:
     - confidence >= threshold → status="annotated"
     - confidence < threshold  → status="review", needs_review=True
6. WebSocket으로 진행률 브로드캐스트
```

#### models.py — 모델 관리 및 파인튜닝

| 메서드 | 경로 | 설명 |
|--------|------|------|
| GET | `/api/models` | 등록된 모델 목록 |
| DELETE | `/api/models/{id}` | 모델 삭제 (is_base=False만 가능) |
| POST | `/api/models/finetune` | 파인튜닝 잡 시작 |
| GET | `/api/models/finetune/{job_id}` | 파인튜닝 상태 |
| WS | `/ws/finetune/{job_id}` | epoch 진행상황 스트리밍 |
| GET | `/api/datasets` | 데이터셋 스냅샷 목록 |
| DELETE | `/api/datasets/{id}` | 스냅샷 삭제 |
| POST | `/api/datasets/upload` | 외부 YOLO ZIP 업로드 |
| POST | `/api/models/finetune-from-datasets` | 다중 스냅샷으로 파인튜닝 |

**파인튜닝 파라미터**:

| 파라미터 | 기본값 | 설명 |
|----------|--------|------|
| project_id | - | 어노테이션 소스 프로젝트 |
| model_name | - | 새 모델 이름 |
| base_model_id | - | 기반 모델 ID |
| replay_count | 300 | 리플레이 샘플 수 (클래스 균형 보정) |
| epochs | 50 | 학습 에포크 수 |
| freeze | 10 | 백본 동결 레이어 수 |
| task | "segment" | 태스크 타입 |

## 6. ML 모델 통합

### 6.1 YOLO11 + SAM2 (세그멘테이션)

```
이미지 입력
   │
   ├── YOLO11 탐지
   │     ├── 신뢰도 필터 (yolo_conf_min)
   │     └── ROI 필터
   │
   ├── 클래스 간 IoU 억제
   │
   ├── SAM2 세그멘테이션 (각 탐지 bbox → 마스크)
   │     └── 임베딩 캐시 활용
   │
   └── 마스크 → 다각형 변환 (mask_to_polygon)
         └── 신뢰도 분류:
               >= threshold → auto
               <  threshold → review
```

### 6.2 YOLO11 단독 (바운딩박스)

- `task="detect"` 프로젝트에서 사용
- SAM2 없음 → 빠른 처리
- bbox 4 꼭짓점을 폴리곤으로 저장 (데이터 형식 통일)

### 6.3 Grounding DINO (제로샷 탐지)

화재·연기 전용 제로샷 탐지기. 별도 학습 없이 텍스트 프롬프트만으로 탐지한다.

```
이미지 입력
   │
   ├── ROI crop (ROI 설정 시, 소형 객체 감지율 향상)
   │
   ├── Grounding DINO 추론
   │     └── 프롬프트: "fire . smoke"
   │         box_threshold=0.15, text_threshold=0.15
   │
   ├── 후처리:
   │     ├── 1. 대형 박스 필터링
   │     │     연기 > 40% 이미지 면적 → 제거
   │     │     화재 > 70% 이미지 면적 → 제거
   │     │
   │     ├── 2. 밝기 기반 트리밍
   │     │     화재 bbox 내 밝은 픽셀 범위로 축소
   │     │
   │     ├── 3. SAM2로 타이트 bbox 재계산
   │     │
   │     └── 4. 겹치는 박스 병합
   │           IoU > 0.3인 동일 클래스 박스 → union bbox
   │
   └── 신뢰도 분류 + FrameTracker (비디오 시퀀스)
```

**등록된 Grounding DINO 모델**:

| id | 이름 | weights_path |
|----|------|-------------|
| 7 | fire_smoke_gdino [bbox] | IDEA-Research/grounding-dino-tiny |
| 8 | fire_smoke_gdino_base [bbox] | IDEA-Research/grounding-dino-base |

`transformers==4.48.0` 필수 (5.x는 BertModel API 변경으로 호환 불가)

### 6.4 SAM2 Video Tracking

CVAT 스타일의 프레임 간 객체 전파 기능.

```
[시드 프레임]
   │
   ├── 저장된 어노테이션에서 bbox 추출
   │
   └── SAM2 VideoPredictor 초기화
         │
         ├── 모든 프레임을 임시 디렉토리에 JPEG 저장
         │
         ├── init_state(frames)
         │
         ├── add_new_points_or_box(frame_idx=0, bbox)
         │
         └── propagate_in_video()
               └── 각 후속 프레임 → 마스크 / bbox 출력
                     → Annotation으로 저장
                     → WebSocket 진행률 브로드캐스트
```

**주의**: SAM2 비디오 모드는 프레임 전체를 메모리에 올리므로, 100프레임 이상이면 처리 시간이 수십 초 소요된다.

## 7. 핵심 워크플로우

### 7.1 자동 어노테이션 워크플로우

```
1. 프로젝트 생성
   - 이름, 레이블(이름+색상), conf_threshold 설정

2. 이미지 업로드
   - 개별 파일 / ZIP / 비디오 프레임 추출

3. (선택) ROI 설정
   - 캔버스에서 다각형 클릭으로 관심 영역 지정

4. 모델 선택
   - segment / detect / gdino 중 하나

5. 자동 어노테이션 잡 시작
   POST /api/projects/{id}/jobs
   - conf_threshold 오버라이드 가능
   - force=true: 기존 어노테이션 삭제 후 재처리

6. WebSocket으로 진행상황 모니터링
   WS /ws/jobs/{job_id}
   → {status, progress, total, auto_count, review_count}

7. 결과 검토
   - "annotated" 이미지: 고신뢰도, 바로 완료
   - "review" 이미지: 저신뢰도, 사용자 확인 필요

8. 수동 편집 (필요 시)
   - 캔버스에서 다각형 꼭짓점 드래그
   - 레이블 변경, 어노테이션 추가/삭제

9. 저장
   PUT /api/images/{id}/annotations

10. 내보내기
    POST /api/projects/{id}/export
```

### 7.2 파인튜닝 워크플로우

```
1. 프로젝트 어노테이션 완료 (충분한 샘플 확보)

2. TrainingPage → 파인튜닝 설정
   - base_model_id: 시작점 모델
   - epochs, freeze, replay_count 설정

3. 파인튜닝 잡 시작
   POST /api/models/finetune

4. 시스템 처리:
   a. 프로젝트 어노테이션 수집
   b. 기존 데이터셋에서 replay_count 샘플 추가 (클래스 균형)
   c. YOLO 학습 디렉토리 구성
   d. GPU 3에서 학습 시작
   e. best.pt 저장 → models/{timestamp}/weights/best.pt
   f. ModelVersion 등록

5. WebSocket으로 epoch 진행상황 모니터링

6. 새 모델을 프로젝트에 연결
   PATCH /api/projects/{id}/model
```

### 7.3 화재/연기 탐지 워크플로우

```
1. CCTV 영상 업로드 (MP4/AVI 등)

2. 프레임 추출
   POST /api/projects/{id}/upload-video
   - fps=1 (1초당 1프레임 권장)
   - startTime/endTime으로 구간 지정

3. 프로젝트 설정
   - 레이블: fire (빨강), smoke (회색)
   - 모델: fire_smoke_gdino_base (id=8)
   - conf_threshold: 0.3~0.4 (낮게 설정)

4. ROI 설정
   - 주차장 영역만 포함
   - 밝은 조명, 하늘, 출입구 등 오탐 영역 제외

5. 자동 어노테이션 잡 시작
   - FrameTracker가 정적 오탐 자동 억제
   - 연속 미탐지 프레임에 결과 전파

6. 결과 검토 및 수동 수정

7. 내보내기 → YOLO 파인튜닝 데이터로 활용
```

### 7.4 비디오 프레임 트래킹 워크플로우

```
1. 시작 프레임에 어노테이션 저장 (bbox)

2. "이 프레임부터 추적" 버튼 클릭
   POST /api/projects/{id}/track
   {
     start_image_id: 현재 이미지 ID,
     mask_mode: false (bbox) / true (polygon)
   }

3. 시스템 처리:
   a. start_image_id 이후 프레임 filename 순 정렬
   b. 시드 bbox 추출
   c. SAM2 VideoPredictor로 전파
   d. 각 프레임 Annotation 저장
   e. WebSocket 진행상황 브로드캐스트

4. 결과 확인 및 오류 수정
```

| POST | `/api/models/finetune-from-datasets` | 다중 스냅샷 파인튜닝 |

## 9. 성능 최적화 기법

### 1. SAM2 임베딩 캐시 (가장 중요)

```python
# OrderedDict LRU 캐시, 최대 20개
cache_key = (img_path, os.path.getmtime(img_path))
```
동일 이미지 반복 클릭 시 1,000ms → 50ms (20배 개선)

### 2. YOLO 모델 지연 로딩 캐시

```python
_yolo_cache[weights_path] = YOLO(weights_path)
```
프로젝트마다 다른 weights_path를 사용해도 중복 로딩 없음.

### 3. Grounding DINO 모델 캐시

```python
_gdino_cache[model_id] = (model, processor)
```
배치 처리 시 매번 HuggingFace 로딩하지 않음.

### 4. ROI Crop 최적화 (GDINO)

전체 이미지 대신 ROI 영역만 잘라서 GDINO 추론 → 소형 객체(1~5% 면적) 감지율 향상.

### 5. 비동기 잡 처리

```python
# 별도 스레드에서 실행, main thread 블록 없음
threading.Thread(target=_run_job, args=(job_id, ...)).start()
```
WebSocket으로 실시간 진행률 스트리밍.

### 6. 비디오 프레임 추출 GPU 가속

ffmpeg CUDA 가속 먼저 시도:
```bash
ffmpeg -hwaccel cuda -i input.mp4 ...
```
실패 시 CPU fallback.

### 7. FrameTracker (GDINO 오탐 억제)

- 동일 bbox가 6프레임 이상 지속되면 → 정적 오탐으로 간주, 억제
- 미탐지 프레임에서 이전 결과 최대 3프레임 전파 (신뢰도 x0.9 감소)

- 근본 해결책: 실제 CCTV 영상 수동 어노테이션 200~300장 → YOLO 파인튜닝

```bash
./db_backup.sh                                  # → backups/annotation_YYYYMMDD_HHMMSS.sql.gz
./db_restore.sh backups/annotation_<date>.sql.gz
python migrate_to_pg.py                         # SQLite → PostgreSQL 일회성 마이그레이션
```

### 학습 실행

**직접 실행**:
```bash
CUDA_VISIBLE_DEVICES=3 venv/bin/python -m ultralytics train \
  model=yolo11x.pt \
  data=datasets/real_fire_smoke_v3/data.yaml \
  epochs=80 imgsz=640 batch=8 \
  optimizer=AdamW lr0=0.001 lrf=0.01 freeze=0
```

> `freeze=0`: 도메인 적응 시 백본 동결 금지 (프리징하면 새 도메인 학습 방해)
> `AdamW lr0=0.001`: SGD보다 파인튜닝에 효과적

**SLURM 클러스터**:
```bash
sbatch train_fire_smoke.sh
```
